A failed configuration migration stalled a firewall policy push. It truncated the authoritative rule base at `/app/data/policy_rules.json` and left the policy compiler at `/app/workflow/compile_policy.go` deciding what to install under draft rules the change advisory board later reversed. Nothing the compiler emits can be trusted until that rule base is rebuilt. A pre-migration snapshot and a journal of the changes the migration posted after it survive beside the truncated file under `/app/data`, alongside the object-group catalogue the rules address each other through. How the snapshot and the journal combine, which rule a change names, what a retraction does, what a later restoration brings back, and how a group whose members name other groups resolves to a set of prefixes are governance decisions, and the rule base is restored in place at `/app/data/policy_rules.json` where the truncated file sits, with both sides of every rule already resolved. Nothing the compiler decides means anything against the truncated file, so that rebuild is what the compiled policy is read from: whatever order you work in, the rule base that is there at the end is the one every graded run is handed.

Then restore the compiler at `/app/workflow/compile_policy.go`, a Go program built with the toolchain installed here. It stays one `package main` in that one file and is compiled from that file alone, so a helper split into a sibling source beside it never reaches the build. That one source is the whole implementation: the compiled program does the work itself and never hands the run off to another program or interpreter, so nothing it relies on at run time sits outside it. Preserve its `--input` and `--output-dir` options and their defaults, and declare no other option; the firewall policy is always read from its fixed absolute path under `/app/data`, and `--input` selects the rule base only. `/app/docs/policy_contract.json` is the output contract: paths, schemas, required-field lists, container shapes, sort orders, and a note against each field saying what that field counts. What those notes leave open -- which is every rule that decides a value rather than names it -- is settled in `/app/incident/network_governance_log.md`, mostly routine change-advisory minutes, where the later dated decision governs. A run writes exactly the three artifacts the contract names -- `summary.json`, `compiled_policy.json` and `exception_queue.jsonl` -- into the directory `--output-dir` selects, which is `/app/output` when the option is not given, and anything an earlier run left in that directory is cleared rather than passed off as this run's output; the contents are what is cleared, since the run does not own the path it writes into, whichever path that is. The contract states the scale a run is expected to handle. Derive every value from the operational inputs: correct against an alternate rule base, identical across reruns. The recovery sources and the rule documents are what this work is done from rather than things it writes, so the pre-migration snapshot, the configuration journal, the object groups, the firewall policy, the governance log and the output contract at `/app/docs/policy_contract.json` all come back byte for byte unchanged, and the frozen snapshot `/app/workflow/.compile_policy.original.go` is left exactly as it is.
